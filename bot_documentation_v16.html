1. Vue d'ensemble & Architecture

Architecture générale

Telegram (canaux configurés) → Signal Parser → MT5 Bridge → MetaTrader 5 ↓ ↓ SL Plafonné 1 MARKET + 2 LIMIT ↓ ↓ Zone / Tolérance ┌── MARKET → exécution immédiate ├── LIMIT 1 → prix - OFFSET_1 (pullback) └── LIMIT 2 → prix - OFFSET_2 (pullback) ↓ TP Dynamique (recalcul si LIMIT rempli) ↓ Clôture P&L Cible (ferme tout + annule LIMITs)

Principe de fonctionnement

Le bot écoute les canaux Telegram configurés, parse les signaux de trading (BUY/SELL), et exécute 1 ordre MARKET + 2 ordres LIMIT par signal. Les LIMITs sont placées à un offset meilleur prix pour catcher un éventuel pullback. Le TP est calculé dynamiquement en fonction du nombre de positions actives et de TP_FIXED_GAIN_USD.

3. Système MARKET + LIMIT

Principe

Chaque signal ouvre 1 position MARKET (exécution immédiate) et 2 ordres LIMIT (pullback à meilleur prix). Les LIMITs sont placés à un offset du prix actuel.

Comment MT5 identifie chaque ordre

CH20-ZN-MK ← canal 20, signal Zone, Market CH20-ZN-L1 ← canal 20, signal Zone, Limit 1 (offset 3$) CH20-ZN-L2 ← canal 20, signal Zone, Limit 2 (offset 6$)

Offsets configurables

OrdreVariableDéfautDescription
LIMIT 1LIMIT_OFFSET_13.0Offset du prix actuel (meilleur prix)
LIMIT 2LIMIT_OFFSET_26.0Offset du prix actuel (encore meilleur prix)

BUY — LIMIT en dessous du prix actuel

Prix actuel: 4418.02 LIMIT 1 = 4418.02 - 3.0 = 4415.02 (achat moins cher) LIMIT 2 = 4418.02 - 6.0 = 4412.02 (achat encore moins cher)

SELL — LIMIT au-dessus du prix actuel

Prix actuel: 3305.00 LIMIT 1 = 3305.00 + 3.0 = 3308.00 (vente plus cher) LIMIT 2 = 3305.00 + 6.0 = 3311.00 (vente encore plus cher)

Lots configurables

OrdreVariableDéfaut
MARKETLOT_MARKET / LOT_TOTAL0.01
LIMIT 1LOT_LIMIT10.01
LIMIT 2LOT_LIMIT20.01

Expiration des LIMITs

Les LIMITs expirent après LIMIT_EXPIRY_MIN minutes (défaut: 30). Si le prix ne les atteint pas, ils sont automatiquement annulés par MT5.

Scénarios de remplissage

CasPositions activesDescription
Cas 1MARKET seulPrix ne revient pas → LIMITs non remplis
Cas 2MARKET + LIMIT 1Prix revient partiellement → L1 rempli
Cas 3MARKET + L1 + L2Prix revient fort → les 2 LIMITs remplis

Configuration

.env: LIMIT_ENABLED=true # Activer les LIMIT orders LIMIT_COUNT=2 # Nombre de LIMIT orders (0, 1 ou 2) LIMIT_OFFSET_1=3.0 # 1er LIMIT à current ± ce montant LIMIT_OFFSET_2=6.0 # 2ème LIMIT à current ± ce montant LOT_LIMIT1=0.01 # Lot pour le LIMIT 1 LOT_LIMIT2=0.01 # Lot pour le LIMIT 2 LIMIT_EXPIRY_MIN=30 # Expiration des LIMIT orders (minutes)

4. TP Dynamique (TP_FIXED_GAIN_USD)

Principe

Le TP n'est pas celui du signal. Il est calculé dynamiquement en fonction de TP_FIXED_GAIN_USD et du nombre de positions actives. Le TP est recalculé à chaque fois qu'un LIMIT se remplit.

Formule

pnl_cible = TP_FIXED_GAIN_USD × multiplicateur price_movement = pnl_cible / nb_positions TP = average_entry ± price_movement

Multiplicateur selon les positions

CasPositionsMultiplicateurpnl_cible
Cas 1MARKET seul1.0TP_FIXED_GAIN_USD × 1
Cas 2MARKET + L1TP_MULTIPE1TP_FIXED_GAIN_USD × TP_MULTIPE1
Cas 3MARKET + L1 + L2TP_MULTIPE2TP_FIXED_GAIN_USD × TP_MULTIPE2

Average entry pondéré

average_entry = (entry_MK × lot_MK + entry_L1 × lot_L1 + entry_L2 × lot_L2) / total_lot

Exemple BUY (TP_FIXED_GAIN_USD=0.5, TP_MULTIPE1=1.5, TP_MULTIPE2=2.0)

MK @ 4418.02 (lot=0.01) L1 @ 4415.037 (lot=0.01) — rempli L2 @ 4412.037 (lot=0.01) — NON rempli ── CAS 2 : MARKET + L1 ── average_entry = (4418.02 + 4415.037) / 2 = 4416.5285 pnl_cible = 0.5 × 1.5 = 0.75$ price_movement = 0.75 / 2 = 0.375 TP = 4416.5285 + 0.375 = 4416.90 Vérification P&L (0.01 lot = 1 oz, 1$ = 1$ P&L) : MK : (4416.90 - 4418.02) × 1 = -1.12$ L1 : (4416.90 - 4415.037) × 1 = +1.86$ Total = +0.75$ ✅

Exemple SELL (TP_FIXED_GAIN_USD=8.0, TP_MULTIPE1=2.0, TP_MULTIPE2=3.0)

MK @ 4412.50 (lot=0.01) L1 @ 4415.30 (lot=0.01) — rempli L2 @ 4418.30 (lot=0.01) — rempli ── CAS 1 : MARKET seul ── pnl_cible = 8.0 × 1 = 8.0$ TP = 4412.50 - 8.0/1 = 4404.50 Gain = +8.00$ ── CAS 2 : MARKET + L1 ── average_entry = (4412.50 + 4415.30) / 2 = 4413.90 pnl_cible = 8.0 × 2.0 = 16.0$ TP = 4413.90 - 16.0/2 = 4405.90 Gain = +16.00$ ── CAS 3 : MARKET + L1 + L2 ── average_entry = (4412.50 + 4415.30 + 4418.30) / 3 = 4415.37 pnl_cible = 8.0 × 3.0 = 24.0$ TP = 4415.37 - 24.0/3 = 4407.37 Gain = +23.99$

Configuration

.env: TP_FIXED_GAIN_USD=8.0 # Gain cible en $ par position TP_MULTIPE1=2.0 # Multiplicateur quand MARKET + L1 TP_MULTIPE2=3.0 # Multiplicateur quand MARKET + L1 + L2

5. Clôture P&L Cible (PHASE 4b)

Principe

À chaque cycle de polling, le bot vérifie si le P&L flottant (lu depuis MT5 via pos.profit + pos.swap) atteint le pnl_cible. Si oui, il :

  1. Ferme toutes les positions actives (MARKET + LIMITs remplis)
  2. Annule tous les LIMITs en attente
  3. Envoie une alerte Telegram

Cycle de vérification

_check_all() (toutes les ~1 seconde) ├── PHASE 4 : _recalculate_tp(entry) → met à jour le TP ├── PHASE 4b : Vérifier P&L flottant >= pnl_cible ? │ ├── OUI → close_all_positions() + cancel_pending_limits() │ └── NON → continuer └── PHASE 5 : Si MARKET fermé → annuler LIMITs restants

Exemple concret

Signal: BUY XAUUSD, TP_FIXED_GAIN_USD=8.0 Positions: MK @ 3305 + L1 @ 3302 (Cas 2, pnl_cible=16.0$) Prix monte à 3321 → P&L flottant = 16.2$ → 16.2$ >= 16.0$ → CLÔTURE ! → MK fermé, L1 fermé, L2 annulé → Alerte: "🎯 P&L CIBLE 16.0$ atteint (16.2$) | 2 fermées + 1 LIMIT annulé"
Important : Le bot ne ferme PAS au TP prix — il surveille le P&L flottant réel. Le TP est un indicateur, la clôture se fait par le P&L.

6. SL Plafonné (MAX_SL_USD)

Principe

Le SL est capé à MAX_SL_USD de l'entrée. Si le SL du signal dépasse cette distance, il est réduit.

BUY @ 4000, signal SL = 3960 (40$), MAX_SL_USD=10 :

distance = |4000 - 3960| = 40$ 40$ > 10$ → SL capé à 3990 (10$ de l'entrée)

BUY @ 4000, signal SL = 3995 (5$), MAX_SL_USD=10 :

distance = |4000 - 3995| = 5$ 5$ ≤ 10$ → SL gardé à 3995

Configuration

.env: MAX_SL_USD=10.0 # Distance SL maximale en $ (défaut 10$)

7. Tolérance Zone (TOLERANCE_ZN)

Principe

La tolérance étend la zone vers le SL pour accepter les signaux dont le prix a légèrement dépassé la zone.

BUY zone 4050-4060, TOLERANCE_ZN=1 :

Prix dans zone [4050, 4060] → MARKET + LIMITs ✅ Prix au-dessus [4060, 4061] → LIMITs seules (pas de MARKET) Prix > 4061 → ANNULÉ ❌

SELL zone 4050-4060, TOLERANCE_ZN=1 :

Prix dans zone [4050, 4060] → MARKET + LIMITs ✅ Prix en-dessous [4049, 4050] → LIMITs seules (pas de MARKET) Prix < 4049 → ANNULÉ ❌

Configuration

.env: TOLERANCE_ZN=1.0 # Tolérance autour de la zone (en $) TOLERANCE_PU=3.0 # Tolérance pour les signaux Prix Unique TOLERANCE_MP=5.0 # Tolérance pour les signaux MARKET PRICE

Signaux Prix Unique (PU)

Signal: BUY @ 4050, SL=4030 Zone calculée: [4050 - TOLERANCE_PU, 4050 + TOLERANCE_PU] = [4047, 4053] Prix dans zone [4047, 4053] → MARKET + 2 LIMITs Prix légèrement au-dessus [4053, 4054] → LIMITs seules Prix hors zone → ANNULÉ

BUY NOW (pas de prix) → Zone = [current - TOLERANCE_MP, current] BUY @ 4050 (avec prix) → Zone = [4050 - TOLERANCE_PU, 4050 + TOLERANCE_PU] Même logique que ZN/PU → MARKET + LIMITs ou LIMITs seules ou ANNULÉ

9. Signal CLOSE & Annulation LIMITs

Principe

Quand un canal envoie un signal CLOSE, le bot :

  1. Ferme toutes les positions ouvertes pour ce canal (via bridge.close_all())
  2. Annule tous les ordres LIMIT en attente pour ce canal (via cancel_pending_limits())
  3. Met à jour le P&L quotidien avec les deals fermés

Avant V16 (bug)

CLOSE → bridge.close_all() → positions fermées ✅ → LIMITs en attente → PAS annulés ❌ (restent dans MT5)

Après V16 (fix)

CLOSE → bridge.close_all() → positions fermées ✅ → manager.active → cancel_pending_limits() → LIMITs annulés ✅

Identification des LIMITs à annuler

Le bot parcourt manager.active et identifie les entrées par :

  • Numéro de canal : CH{num}- dans le commentaire MT5
  • Symbole : si un symbole spécifique est mentionné dans le CLOSE

10. Filling Mode Fallback

Problème (V14)

Les LIMIT orders utilisaient ORDER_FILLING_RETURN en dur. Certains brokers/symboles ne supportent pas ce mode → erreur 10013 (Invalid Price) systématique.

Solution (V16)

Le bot essaie les filling modes dans l'ordre, comme pour les MARKET orders :

Filling modes à tester (selon sym.filling_mode) : 1. ORDER_FILLING_FOK (Fill Or Kill) 2. ORDER_FILLING_IOC (Immediate Or Cancel) 3. ORDER_FILLING_RETURN (Return) ↓ Essayer chaque mode jusqu'au succès ├── Succès → break (passer au LIMIT suivant) └── Échec → essayer le mode suivant └── Tous échoués → log warning

Résolution du symbole

Les LIMIT orders utilisent bridge._sym(symbol) au lieu de mt5.symbol_info(symbol). Cela résout les suffixes de broker (ex: XAUUSD → XAUUSDm).

Pourquoi MARKET marchait et pas LIMIT :
MARKET utilisait bridge._sym() → résolution automatique du suffixe → OK
LIMIT utilisait mt5.symbol_info() direct → symbole introuvable → 10013

13. Exemples complets (BUY & SELL)

Exemple 1 : BUY ZONE — Cas 1 (MARKET seul)

Signal : XAUUSD BUY 4000 4010, TP 4050, SL 3970 Config : TP_FIXED_GAIN_USD=8.0, LIMIT_OFFSET_1=3, LIMIT_OFFSET_2=6 Calcul : Prix actuel = 4005 (dans zone [4000, 4010]) avg_entry = (4000 + 4010) / 2 = 4005 TP = 4005 + 8.0 = 4013.00 SL = _cap_sl(BUY, 4005, 3970, 10) = 3995 (capé à 10$) Ordres : MARKET @ 4005.00 — lot=0.01, TP=4013, SL=3995 LIMIT 1 @ 4002.00 — lot=0.01, TP=4013, SL=3995 LIMIT 2 @ 3999.00 — lot=0.01, TP=4013, SL=3995 Résultat : Prix monte → P&L flottant atteint 8.0$ → Bot ferme MARKET, annule LIMIT 1 et LIMIT 2 → Gain net : +8.00$

Exemple 2 : BUY ZONE — Cas 2 (MARKET + L1)

Signal : XAUUSD BUY 4000 4010, TP 4050, SL 3970 Config : TP_FIXED_GAIN_USD=8.0, TP_MULTIPE1=2.0 Ordres : MARKET @ 4005.00 — exécuté immédiatement LIMIT 1 @ 4002.00 — rempli (prix revient à 4002) LIMIT 2 @ 3999.00 — NON rempli Recalcul TP : avg = (4005 + 4002) / 2 = 4003.5 pnl_cible = 8.0 × 2.0 = 16.0$ TP = 4003.5 + 16.0/2 = 4011.50 Résultat : P&L flottant atteint 16.0$ → Bot ferme MARKET + L1, annule LIMIT 2 → Gain net : +16.00$

Exemple 3 : SELL ZONE — Cas 3 (MARKET + L1 + L2)

Signal : XAUUSD SELL 4410 4415, TP 4400, SL 4450 Config : TP_FIXED_GAIN_USD=0.5, TP_MULTIPE1=1.5, TP_MULTIPE2=2.0 Ordres : MARKET @ 4412.50 — exécuté LIMIT 1 @ 4415.50 — rempli (prix monte) LIMIT 2 @ 4418.50 — rempli (prix monte encore) Recalcul TP : avg = (4412.50 + 4415.50 + 4418.50) / 3 = 4415.50 pnl_cible = 0.5 × 2.0 = 1.0$ TP = 4415.50 - 1.0/3 = 4415.17 Résultat : P&L flottant atteint 1.0$ → Bot ferme tout → Gain net : +1.00$
