1. Vue d'ensemble & Architecture

Architecture générale

Telegram (canaux configurés) → Signal Parser → MT5 Bridge → MetaTrader 5 ↓ ↓ SL Plafonné 1 MARKET + 2 LIMIT ↓ ↓ Zone / Tolérance ┌── MARKET → exécution immédiate ├── LIMIT 1 → prix - OFFSET_1 (pullback) └── LIMIT 2 → prix - OFFSET_2 (pullback) ↓ TP Dynamique (recalcul si LIMIT rempli) ↓ Clôture P&L Cible (ferme tout + annule LIMITs)

Principe de fonctionnement

Le bot écoute les canaux Telegram configurés, parse les signaux de trading (BUY/SELL), et exécute 1 ordre MARKET + 2 ordres LIMIT par signal. Les LIMITs sont placées à un offset meilleur prix pour catcher un éventuel pullback. Le TP est calculé dynamiquement en fonction du nombre de positions actives et de TP_FIXED_GAIN_USD.

Clôture automatique par gain

2. Système MARKET + LIMIT

Principe

Chaque signal ouvre 1 position MARKET (exécution immédiate) et 2 ordres LIMIT (pullback à meilleur prix). Les LIMITs sont placés à un offset du prix actuel.

Comment MT5 identifie chaque ordre

CH20-ZN-MK ← canal 20, signal Zone, Market CH20-ZN-L1 ← canal 20, signal Zone, Limit 1 (offset 3$) CH20-ZN-L2 ← canal 20, signal Zone, Limit 2 (offset 6$)

Offsets configurables

OrdreVariableDéfautDescription
LIMIT 1LIMIT_OFFSET_13.0Offset du prix actuel (meilleur prix)
LIMIT 2LIMIT_OFFSET_26.0Offset du prix actuel (encore meilleur prix)

BUY — LIMIT en dessous du prix actuel

Prix actuel: 4418.02 LIMIT 1 = 4418.02 - 3.0 = 4415.02 (achat moins cher) LIMIT 2 = 4418.02 - 6.0 = 4412.02 (achat encore moins cher)

SELL — LIMIT au-dessus du prix actuel

Prix actuel: 3305.00 LIMIT 1 = 3305.00 + 3.0 = 3308.00 (vente plus cher) LIMIT 2 = 3305.00 + 6.0 = 3311.00 (vente encore plus cher)

Lots configurables

OrdreVariableDéfaut
MARKETLOT_MARKET / LOT_TOTAL0.01
LIMIT 1LOT_LIMIT10.01
LIMIT 2LOT_LIMIT20.01

Expiration des LIMITs

Les LIMITs expirent après LIMIT_EXPIRY_MIN minutes (défaut: 30). Si le prix ne les atteint pas, ils sont automatiquement annulés par MT5. Quand toutes les positions d'un signal sont fermées (TP/SL/CLOSE), les LIMITs restants sont annulés immédiatement.

Scénarios de remplissage

CasPositions activespnl_cibleDescription
Cas 1MARKET seulTP_FIXED_GAIN_USD × 1Prix ne revient pas → LIMITs non remplis
Cas 2MARKET + LIMIT 1TP_FIXED_GAIN_USD × TP_MULTIPE1Prix revient partiellement → L1 rempli
Cas 3MARKET + L1 + L2TP_FIXED_GAIN_USD × TP_MULTIPE2Prix revient fort → les 2 LIMITs remplis

Configuration

.env: LIMIT_ENABLED=true # Activer les LIMIT orders LIMIT_COUNT=2 # Nombre de LIMIT orders (0, 1 ou 2) LIMIT_OFFSET_1=3.0 # 1er LIMIT à current ± ce montant LIMIT_OFFSET_2=6.0 # 2ème LIMIT à current ± ce montant LOT_MARKET=0.01 # Lot pour le MARKET LOT_LIMIT1=0.01 # Lot pour le LIMIT 1 LOT_LIMIT2=0.01 # Lot pour le LIMIT 2 LIMIT_EXPIRY_MIN=30 # Expiration des LIMIT orders (minutes)

3. TP Dynamique (TP_FIXED_GAIN_USD)

Principe

Le TP n'est pas celui du signal. Il est calculé dynamiquement en fonction de TP_FIXED_GAIN_USD et du nombre de positions actives. Le TP est recalculé à chaque fois qu'un LIMIT se remplit.

Formule

pnl_cible = TP_FIXED_GAIN_USD × multiplicateur price_movement = pnl_cible / nb_positions TP = average_entry ± price_movement

Multiplicateur selon les positions

CasPositionsMultiplicateurpnl_cible (avec FIXED=7$)
Cas 1MARKET seul1.07.00$
Cas 2MARKET + L1TP_MULTIPE1 (1.5)10.50$
Cas 3MARKET + L1 + L2TP_MULTIPE2 (2.0)14.00$

Average entry pondéré

average_entry = (entry_MK × lot_MK + entry_L1 × lot_L1 + entry_L2 × lot_L2) / total_lot

Exemple BUY (TP_FIXED_GAIN_USD=7.0, TP_MULTIPE1=1.5, TP_MULTIPE2=2.0)

MK @ 4393.75 (lot=0.01) L1 @ 4390.81 (lot=0.01) — rempli L2 @ 4387.81 (lot=0.01) — NON rempli ── CAS 1 : MARKET seul ── pnl_cible = 7.0 × 1 = 7.0$ TP = 4393.75 + 7.0 = 4400.75 Gain = +7.00$ ── CAS 2 : MARKET + L1 ── average_entry = (4393.75 + 4390.81) / 2 = 4392.28 pnl_cible = 7.0 × 1.5 = 10.50$ TP = 4392.28 + 10.50/2 = 4397.53 Gain = +10.50$ ── CAS 3 : MARKET + L1 + L2 ── average_entry = (4393.75 + 4390.81 + 4387.81) / 3 = 4390.79 pnl_cible = 7.0 × 2.0 = 14.0$ TP = 4390.79 + 14.0/3 = 4395.46 Gain = +14.00$
Retry : Si modify_sl_tp échoue (spread trop large, prix trop proche), le TP sera retenté au cycle suivant. Le flag _tp_calculated_for n'est mis à jour que si au moins un TP a été modifié avec succès.

Configuration

.env: TP_FIXED_GAIN_USD=7.0 # Gain cible en $ par position TP_MULTIPE1=1.5 # Multiplicateur quand MARKET + L1 TP_MULTIPE2=2.0 # Multiplicateur quand MARKET + L1 + L2

4. Clôture P&L Cible (PHASE 4b)

Principe

À chaque cycle de polling (~1s), le bot vérifie si le P&L flottant (lu depuis MT5 via pos.profit + pos.swap) atteint le pnl_cible. Si oui :

  1. Ferme toutes les positions actives (MARKET + LIMITs remplis)
  2. Annule tous les LIMITs en attente
  3. Envoie une alerte Telegram

Cycle de vérification

_check_all() (toutes les ~1 seconde) ├── PHASE 4 : _recalculate_tp(entry) → met à jour le TP dynamiquement ├── PHASE 4b : Vérifier P&L flottant >= pnl_cible ? │ ├── OUI → close_all_positions() + cancel_pending_limits() │ └── NON → continuer └── PHASE 5 : Si MARKET fermé → annuler LIMITs restants

Exemple concret

Signal: BUY XAUUSD, TP_FIXED_GAIN_USD=7.0 Positions: MK @ 3305 + L1 @ 3302 (Cas 2, pnl_cible=10.50$) Prix monte → P&L flottant = 10.60$ → 10.60$ >= 10.50$ → CLÔTURE ! → MK fermé, L1 fermé, L2 annulé → Alerte: "🎯 P&L CIBLE 10.50$ atteint (10.60$) | 2 fermées + 1 LIMIT annulé"
Important : Le bot ne ferme PAS au TP prix — il surveille le P&L flottant réel depuis MT5. Le TP est un indicateur, la clôture se fait par le P&L.

5. SL Plafonné (MAX_SL_USD)

Principe

Le SL est capé à MAX_SL_USD de l'entrée. Si le SL du signal dépasse cette distance, il est réduit.

BUY @ 4000, signal SL = 3960 (40$), MAX_SL_USD=10 :

distance = |4000 - 3960| = 40$ 40$ > 10$ → SL capé à 3990 (10$ de l'entrée)

BUY @ 4000, signal SL = 3995 (5$), MAX_SL_USD=10 :

distance = |4000 - 3995| = 5$ 5$ ≤ 10$ → SL gardé à 3995

Configuration

.env: MAX_SL_USD=10.0 # Distance SL maximale en $ (défaut 10$)

6. Tolérance Zone

Principe

La tolérance étend la zone vers le SL pour accepter les signaux dont le prix a légèrement dépassé la zone.

BUY zone 4050-4060, TOLERANCE_ZN=1 :

Prix dans zone [4050, 4060] → MARKET + LIMITs ✅ Prix au-dessus [4060, 4061] → LIMITs seules (pas de MARKET) Prix > 4061 → ANNULÉ ❌

SELL zone 4050-4060, TOLERANCE_ZN=1 :

Prix dans zone [4050, 4060] → MARKET + LIMITs ✅ Prix en-dessous [4049, 4050] → LIMITs seules (pas de MARKET) Prix < 4049 → ANNULÉ ❌

8. Signal CLOSE & Annulation LIMITs

Principe

Quand un canal envoie un signal CLOSE, le bot :

  1. Ferme toutes les positions ouvertes pour ce canal (via bridge.close_all())
  2. Annule tous les ordres LIMIT en attente pour ce canal (via cancel_pending_limits())
  3. Met à jour le P&L quotidien avec les deals fermés

Annulation automatique des LIMITs restants

En plus du signal CLOSE, les LIMITs sont automatiquement annulés quand :

  • Toutes les positions sont fermées (TP/SL) — les LIMITs orphelins sont annulés au cycle suivant
  • P&L cible atteint — fermeture + annulation en une seule opération
  • News haute impact — fermeture + annulation via NewsManager
  • Nouveau signal du même canal — l'ancien signal est fermé et ses LIMITs annulés
V16 fix : Avant, les LIMITs restaient actifs dans MT5 après la fermeture des positions. Maintenant, ils sont annulés dans tous les cas de fermeture.

9. Filling Mode Fallback

Problème (V14)

Les LIMIT orders utilisaient ORDER_FILLING_RETURN en dur. Certains brokers/symboles ne supportent pas ce mode → erreur 10013 (Invalid Price) systématique.

Solution (V16)

Le bot essaie les filling modes dans l'ordre, comme pour les MARKET orders :

Filling modes à tester (selon sym.filling_mode) : 1. ORDER_FILLING_FOK (Fill Or Kill) 2. ORDER_FILLING_IOC (Immediate Or Cancel) 3. ORDER_FILLING_RETURN (Return) ↓ Essayer chaque mode jusqu'au succès ├── Succès → break (passer au LIMIT suivant) └── Échec → essayer le mode suivant └── Tous échoués → log warning

Résolution du symbole

Les LIMIT orders utilisent bridge._sym(symbol) au lieu de mt5.symbol_info(symbol). Cela résout les suffixes de broker (ex: XAUUSD → XAUUSDm).

Pourquoi MARKET marchait et pas LIMIT :
MARKET utilisait bridge._sym() → résolution automatique du suffixe → OK
LIMIT utilisait mt5.symbol_info() direct → symbole introuvable → 10013

12. Exemples complets

Exemple 1 : BUY ZONE — Cas 1 (MARKET seul)

Signal : XAUUSD BUY 4000 4010, SL 3970 Config : TP_FIXED_GAIN_USD=7.0, LIMIT_OFFSET_1=3, LIMIT_OFFSET_2=6 Calcul : Prix actuel = 4005 (dans zone [4000, 4010]) avg_entry = (4000 + 4010) / 2 = 4005 TP = 4005 + 7.0 = 4012.00 SL = _cap_sl(BUY, 4005, 3970, 10) = 3995 (capé à 10$) Ordres : MARKET @ 4005.00 — lot=0.01, TP=4012, SL=3995 LIMIT 1 @ 4002.00 — lot=0.01, TP=4012, SL=3995 LIMIT 2 @ 3999.00 — lot=0.01, TP=4012, SL=3995 Résultat : Prix monte → P&L flottant atteint 7.0$ → Bot ferme MARKET, annule LIMIT 1 et LIMIT 2 → Gain net : +7.00$

Exemple 2 : BUY ZONE — Cas 2 (MARKET + L1)

Signal : XAUUSD BUY 4000 4010, SL 3970 Config : TP_FIXED_GAIN_USD=7.0, TP_MULTIPE1=1.5 Ordres : MARKET @ 4005.00 — exécuté immédiatement LIMIT 1 @ 4002.00 — rempli (prix revient à 4002) LIMIT 2 @ 3999.00 — NON rempli Recalcul TP : avg = (4005 + 4002) / 2 = 4003.5 pnl_cible = 7.0 × 1.5 = 10.50$ TP = 4003.5 + 10.50/2 = 4008.75 Résultat : P&L flottant atteint 10.50$ → Bot ferme MARKET + L1, annule LIMIT 2 → Gain net : +10.50$

Exemple 3 : BUY ZONE — Cas 3 (MARKET + L1 + L2)

Signal : XAUUSD BUY 4000 4010, SL 3970 Config : TP_FIXED_GAIN_USD=7.0, TP_MULTIPE2=2.0 Ordres : MARKET @ 4005.00 — exécuté LIMIT 1 @ 4002.00 — rempli LIMIT 2 @ 3999.00 — rempli Recalcul TP : avg = (4005 + 4002 + 3999) / 3 = 4002.0 pnl_cible = 7.0 × 2.0 = 14.0$ TP = 4002.0 + 14.0/3 = 4006.67 Résultat : P&L flottant atteint 14.0$ → Bot ferme tout → Gain net : +14.00$

Exemple 4 : SELL avec LIMITs

Signal : XAUUSD SELL 4410 4415, SL 4450 Config : TP_FIXED_GAIN_USD=7.0, TP_MULTIPE1=1.5 Ordres : MARKET @ 4412.50 — exécuté LIMIT 1 @ 4415.50 — rempli (prix monte) LIMIT 2 @ 4418.50 — NON rempli Recalcul TP : avg = (4412.50 + 4415.50) / 2 = 4414.0 pnl_cible = 7.0 × 1.5 = 10.50$ TP = 4414.0 - 10.50/2 = 4408.75 Résultat : Prix descend → P&L atteint 10.50$ → Gain net : +10.50$

Exemple 5 : LIMIT échoue (filling mode)

Avant V16 : LIMIT 1 → ORDER_FILLING_RETURN → 10013 → ÉCHEC ❌ LIMIT 2 → ORDER_FILLING_RETURN → 10013 → ÉCHEC ❌ Après V16 : LIMIT 1 → FOK → 10013 → IOC → SUCCÈS ✅ LIMIT 2 → FOK → 10013 → IOC → SUCCÈS ✅
