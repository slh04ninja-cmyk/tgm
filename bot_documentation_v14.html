1. Vue d'ensemble & Architecture

Architecture générale

Telegram (52 canaux, dossier ou .env) → Signal Parser V14 → MT5 Bridge → MetaTrader 5 (Exness) ↓ ↓ SL Plafonné 5 positions × signal (A/B Testing) ↓ ↓ Tolerance Zone ┌── P1: TP Fixe (BE classique) ├── P2: BE Escaladé ├── P3: Trailing Stop ├── P4a: Partial Quick (TP direct) └── P4b: Partial Trail (Trailing) ↓ Fin de journée (20h UTC) ↓ Rapport texte + PDF → Telegram

Principe de fonctionnement

Le bot écoute les canaux Telegram configurés, parse les signaux de trading (BUY/SELL), et exécute 5 ordres MARKET simultanés par signal pour comparer différentes stratégies de gestion (A/B Testing). Le SL est plafonné à une distance maximale, et un rapport quotidien est généré automatiquement à la fin de la journée.

4. Multi-Positions (A/B Testing)

Principe

Chaque signal ouvre 5 positions MARKET simultanées au même prix, même lot (0.01), et les gère avec des méthodes différentes pour comparer les performances.

PositionRôleTPGestion
P1tp_fixeTP du signalBE classique : profit ≥ PNL_TRIGGER_USD → SL à entry ± BE_USD
P2be_scaleentry ± 15$BE escaladé : +4$→BE, +8$→+2$, +12$→+5$
P3trailingAucun (lointain)Trailing stop de TRAILING_STOP_USD (défaut 7$)
P4apartial_quickentry ± 5$TP direct — MT5 ferme automatiquement
P4bpartial_trailAucun (lointain)Trailing stop de PARTIAL_TRAIL_USD (défaut 5$)

Comment MT5 identifie chaque position

CH1-ZN1-P1 ← canal 1, zone 1, méthode TP Fixe CH1-ZN1-P2 ← canal 1, zone 1, méthode BE Escaladé CH1-ZN1-P3 ← canal 1, zone 1, méthode Trailing CH1-ZN1-P4a ← canal 1, zone 1, méthode Partial Quick CH1-ZN1-P4b ← canal 1, zone 1, méthode Partial Trail

P2 : BE Escaladé (paliers configurables)

Profit atteintSL déplacé àVariable .env
+4$entry (BE neutre)P2_TRIGGER_1 / P2_SL_OFFSET_1
+8$entry + 2$P2_TRIGGER_2 / P2_SL_OFFSET_2
+12$entry + 5$P2_TRIGGER_3 / P2_SL_OFFSET_3

Flux d'exécution

Signal reçu (BUY zone 4050-4060) ↓ _open_multi_positions() ├── P1 → MARKET lot=0.01 TP=4070 SL=4030 ├── P2 → MARKET lot=0.01 TP=4065 SL=4030 ├── P3 → MARKET lot=0.01 TP=4560 SL=4030 (TP lointain) ├── P4a → MARKET lot=0.01 TP=4055 SL=4030 (TP 5$) └── P4b → MARKET lot=0.01 TP=4560 SL=4030 (TP lointain) ↓ TradeManager._check_all() → dispatch par rôle ├── P1 → _manage_tp_fixe() ├── P2 → _manage_be_scale() ├── P3 → _manage_trailing() ├── P4a → _manage_partial_quick() (pass — TP gère) └── P4b → _manage_partial_trail()

5. SL Plafonné (MAX_SL_USD)

Principe

Le SL est capé à MAX_SL_USD de l'entrée. Si le SL du signal dépasse cette distance, il est réduit.

BUY @ 4000, signal SL = 3960 (40$) → SL capé à 3990 (10$) ← MAX_SL_USD=10 BUY @ 4000, signal SL = 3995 (5$) → SL gardé à 3995 ← 5$ < 10$, OK

Où le SL est capé

Le _cap_sl() est appelé dans 4 endroits :

  1. Ouverture d'une position zone (ZN1/ZN2)
  2. Ouverture d'une position prix unique (PU1/PU2)
  3. Ouverture d'une Quick Alert (AL-MP)
  4. Fusion d'un QA avec un signal complet

Configuration

.env: MAX_SL_USD=10.0 # Distance SL maximale en $

6. Tolérance Zone (TOLERANCE_ZN)

Principe

La tolérance étend la zone vers le SL pour accepter les signaux dont le prix a légèrement dépassé la zone.

SELL zone 4050-4060, SL=4080, TOL=1 :

Prix ≥ 4060 → ZN2 ✅ 4049 ≤ Prix < 4060 → ZN1 ✅ (zone étendue de 1$) Prix < 4049 → ANNULÉ ❌

BUY zone 4050-4060, SL=4030, TOL=1 :

Prix ≤ 4050 → ZN2 ✅ 4050 < Prix ≤ 4061 → ZN1 ✅ (zone étendue de 1$) Prix > 4061 → ANNULÉ ❌

Configuration

.env: TOLERANCE_ZN=1.0 # Tolérance autour de la zone (en $)

9. Trade Manager & Gestion par rôle

Boucle de polling (1s)

_check_all() (toutes les 1s) ├── Refresh position cache (1 appel MT5) ├── Vérifier fin de journée → _shutdown_end_of_day() ├── Vérifier P&L limite → _shutdown_for_daily_limit() ├── Max Drawdown tracking └── Pour chaque entrée active: ├── Détecter les tickets fermés → P&L + alerte ├── Retirer les entrées terminées → _completed_entries └── Gestion par rôle (P1-P4b)

Gestion P1 (TP Fixe)

BE classique : Quand profit ≥ PNL_TRIGGER_USD → SL à entry ± BE_USD TP à entry ± TP_FIXED_GAIN_USD

Gestion P2 (BE Escaladé)

Paliers configurables : +P2_TRIGGER_1$ → SL à entry + P2_SL_OFFSET_1 +P2_TRIGGER_2$ → SL à entry + P2_SL_OFFSET_2 +P2_TRIGGER_3$ → SL à entry + P2_SL_OFFSET_3

Gestion P3 (Trailing)

Trailing stop : SL = prix_actuel - TRAILING_STOP_USD Le SL ne recule JAMAIS (condition: new_sl > current_sl)

Gestion P4a (Partial Quick)

TP direct à entry ± P4A_TP_OFFSET (5$) MT5 ferme automatiquement quand le prix atteint le TP Pas de gestion manuelle (pass)

Gestion P4b (Partial Trail)

Trailing stop : SL = prix_actuel - PARTIAL_TRAIL_USD Le SL ne recule JAMAIS (condition: new_sl > current_sl)

10. Rapport Quotidien (Texte + PDF)

Contenu du rapport

SectionDonnées
Résumé globalP&L réalisé, trades, wins, losses, winrate, max drawdown
Par méthodeP1 TP Fixe, P2 BE Scale, P3 Trailing, P4 Partial (50/50)
Par type de signalZN1, ZN2, PU1, PU2, MP, AL — canaux, trades, winrate, avg gain/perte
Par canalCH1, CH2... avec nom (Channels.txt), triés par P&L
ClôturesNombre de TP vs SL avec P&L

Données persistantes (_completed_entries)

Les trades terminés sont sauvegardés dans _completed_entries tout au long de la journée. Le rapport combine self.active + _completed_entries pour garantir que les données ne sont pas perdues quand les positions sont fermées.

Génération PDF

Le PDF est généré avec fpdf2 (auto-installé au démarrage). Les emojis Unicode sont nettoyés des noms de canaux pour éviter les crashs. Le fichier est sauvé dans le répertoire du bot.

Configuration

.env: ALERT_DAILY_PERFORMANCE=true # Rapport quotidien activé TRADING_END_HOUR=20 # Heure de génération du rapport

11. Fermeture Automatique (Fin de journée)

Comportement

Heure UTCAction
TRADING_START_HOURRESET JOURNALIER — nouveau jour, flags reset
Plage horaireTrading normal (signaux + gestion P1-P4b)
TRADING_END_HOURFermeture automatique : toutes les positions + annulation ordres + rapport
Hors plageNouveaux signaux ignorés

Flag _end_of_day_done

Le flag _end_of_day_done évite les fermetures répétées. Il est automatiquement reset au début du nouveau jour de trading.

14. Validation TimesFM

Principe

TimesFM est un modèle de prévision temporelle (Google, 200M paramètres) qui valide la direction du signal avant exécution.

Critères de validation

CritèreVariableDéfaut
Direction prédite = direction du signal—Obligatoire
Amplitude minimaleTIMESFM_MIN_MOVE_PIPS5.0 pips
Confiance minimaleTIMESFM_MIN_CONFIDENCE0.35

Configuration

.env: TIMESFM_ENABLED=true TIMESFM_TIMEFRAME=M5 TIMESFM_CONTEXT_BARS=256 TIMESFM_HORIZON=12 TIMESFM_SYMBOL=XAUUSDm
