2. Types de signaux

Le parser classifie chaque message TRADE selon : zone réelle (low ≠ high), prix unique, quick alert avec prix, ou quick alert sans prix (« NOW »).

TypeOrigineComportement
ZNZone réelle (low < high) + TPPrix dans la zone (± TOLERANCE_ZN) → MK+L1+L2. Hors zone → L3/L4 (si TRADE_HORS_ZONE=true) sinon REFUSE HORS ZONE
PUPrix unique (entry)Zone convertie = [entry ± TOLERANCE_PU]. Prix dans la zone → MK+L1+L2 ; sinon REFUSE HORS ZONE
QAQuick Alert avec prix (« BUY 4439 »)Zone = [entry ± TOLERANCE_PU]. Prix dans la zone → MK+L1+L2 ; sinon REFUSE HORS ZONE. SL = entry ± QUICK_ALERT_SL_OFFSET (capé MAX_SL_USD)

ALAnnonce des quick alerts (log)Ce n'est pas un signal distinct : le log d'entrée affiche « CH{num}-AL » pour un quick alert, l'exécution utilise le label QA ou MP. Commentaire MT5 = CH{num}-QA / CH{num}-MP (jamais -AL)

Détection direction masquée : le parser normalise (NFKC) et détecte Entry/TP/SL même si le mot BUY/SELL est absent du message.

Anti-spam (SPAM_STRONG) : les messages contenant result/recap/hit/pips restent du spam même avec BUY/SELL — jamais exécutés.

3. Gestion des trades type ZN

3.1 Cas 1 — Prix dans la zone

Situation du prix par rapport à la zone (TOLERANCE_ZN = 1$) :

  • BUY : in_zone = low ≤ prix ≤ high + TOLERANCE_ZN ; hors zone = prix > high + TOLERANCE_ZN ; bord = high
  • SELL : in_zone = low − TOLERANCE_ZN ≤ prix ≤ high ; hors zone = prix < low − TOLERANCE_ZN ; bord = low

Prix dans la zone (± TOLERANCE_ZN) → exécution :

OrdrePrixLotCommentaire MT5
MARKETprix actuel (market)0.01 (LOT_MARKET)CH{num}-ZN-MK
LIMIT L1current ∓ 3.0 (LIMIT_OFFSET_1)0.01CH{num}-ZN-L1
LIMIT L2current ∓ 6.0 (LIMIT_OFFSET_2)0.01CH{num}-ZN-L2

BUY → limites sous le prix (pullback haussier) ; SELL → limites au-dessus. Expiration des LIMITs : LIMIT_EXPIRY_MIN (30 min).

SL (cas 1)

  • SL unique pour MK+L1+L2, capé sur le prix d'exécution réel : BUY sl = max(sl_signal, current − MAX_SL_USD) ; SELL sl = min(sl_signal, current + MAX_SL_USD)
  • Le SL n'est jamais rapproché contre le trade. Correction post-ouverture (v17.4e) sur prix d'ouverture réel avec sl_wanted au recovery

TP (cas 1)

  • TP initial : current ± TP_FIXED_GAIN_USD (7$) — posé sur MK, L1 et L2 (le TP du signal est ignoré)
  • Recalcul dynamique (boucle 0.3s, dès le 1er cycle) : MK seul → TP = entry_MK ± 7 → MK ferme à +7.00$ exactement ; MK+L1 → TP = avg ± 5.25 (cible 10.5$) ; MK+L1+L2 → TP = avg ± 4.67 (cible 14$)
Exemple — Cas 1 : « XAUUSD BUY zone 4437–4440 TP 4455 SL 4428 », prix actuel = 4438 (dans la zone)
→ MK @4438 + L1 @4435 + L2 @4432 (lots 0.01)
→ SL : signal 4428, distance 10$ ≤ MAX_SL_USD (12$) → SL 4428
→ TP initial : 4438 + 7 = 4445 (posé sur les 3 ordres)
→ L1/L2 ne se remplissent pas : recalcul → TP = 4445 → MK ferme à +7.00$, LIMITs annulées
→ Si L1 remplit : TP commun = avg(MK,L1) ± 5.25 (cible 10.5$)
Log : CH110-ZN | ACCEPTE | MK=4438 | L1=4435 | L2=4432

3.2 Cas 2 — Prix hors zone (L3/L4)

Quand le prix est hors zone (au-delà de ± TOLERANCE_ZN), le bot vérifie dans l'ordre :

  1. dist = |prix − bord_zone| (bord = high + TOLERANCE_ZN pour BUY, low − TOLERANCE_ZN pour SELL)
  2. dist > MAX_DISTANCE (3$) → REFUSE HORS ZONE (vérification AVANT d'ouvrir)
  3. TRADE_HORS_ZONE = false → REFUSE HORS ZONE (refus simple)
  4. TRADE_HORS_ZONE = true et dist ≤ 3$ → ouverture L3 + L4 :
OrdrePrixLotCommentaire MT5
LIMIT L3bord de zone (high BUY / low SELL)0.01CH{num}-ZN-L3
LIMIT L4milieu de zone (low+high)/20.01CH{num}-ZN-L4

Jamais de MARKET (on n'entre pas à un mauvais prix, on attend le retour du prix dans la zone).

SL (cas 2)

SL commun ancré au bord : SL = L3 ∓ MAX_SL_USD (12$) — même SL pour L3 et L4.

TP (cas 2)

  • TP initial : L3 ± TP_FIXED_GAIN_USD (7$) — posé sur L3 ET L4
  • TP dynamique : L3 seule remplie → TP = entry_L3 ± 7 → L3 ferme à +7.00$ exactement ; L3 + L4 remplies → TP = avg(L3,L4) ± 5.25 → cible totale 10.5$ (7 × TP_MULTIPE1)

Expiration et annulation (cas 2)

  • Expiration : LIMIT_EXPIRY_MIN (30 min) — réutilise la variable des ordres normaux
  • Annulation : si le prix s'éloigne de > MAX_DISTANCE de L3 (le bord) → annuler L3/L4 (référence = L3, pas le milieu de zone)
Exemple — Cas 2 : « XAUUSD BUY zone 4437–4440 TP 4455 SL 4428 », prix actuel = 4442 (hors zone : 4442 > 4440 + 1)
→ dist = 4442 − 4441 = 1$ ≤ MAX_DISTANCE (3$) ✓ (bord = 4440 + 1)
→ TRADE_HORS_ZONE=true → ouverture : L3 @4440 (bord) + L4 @4438.5 (milieu), pas de MARKET
→ SL = 4440 − 12 = 4428 (commun aux 2)
→ TP initial : 4440 + 7 = 4447 (L3) et 4438.5 + 7 = 4445.5 (L4)
→ L3 seule se remplit → TP recalculé = 4447 → L3 ferme à +7.00$, L4 annulée
→ L3 + L4 remplies → TP commun = avg(L3,L4) ± 5.25 → cible 10.5$
Log : CH110-ZN | BUY | HORS-ZONE | L3=4440 | L4=4438.5 | SL=4428
REFUSE HORS ZONE (dist > 3$) : prix = 4445 → dist = 4445 − 4441 = 4$ > 3$ → CH110-ZN | REFUSE HORS ZONE (dist 4.00$ > MAX_DISTANCE=3) — rien n'est ouvert.
Autres types : PU / QA → REFUSE HORS ZONE (refus simple, jamais de L3/L4) — AL n'est que le mode log des QA ; MP → jamais refusé (sa zone est créée autour du prix courant).

4. Gestion des trades PU / MP / QA

Les signaux à prix unique (PU) et les quick alerts (QA avec prix, MP sans prix) sont convertis en zone autour de l'entrée puis gérés en MARKET + LIMITs. Jamais de L3/L4 pour ces types : soit acceptés (MK+L1+L2 ou LIMITs seules), soit REFUSE HORS ZONE.

4.1 PU — Prix unique (Entry)

Zone convertie : [entry ± TOLERANCE_PU] (3$)

  • BUY : in_zone = entry − TOLERANCE_PU < prix ≤ entry + TOLERANCE_PU
  • SELL : in_zone = entry − TOLERANCE_PU ≤ prix < entry + TOLERANCE_PU
  • Prix dans la zone → MK + L1 + L2 ; sinon → REFUSE HORS ZONE (même logique que MP : zone symétrique, pas de bande étendue TOLERANCE_ZN)
  • SL : _cap_sl(action, entry, sl, MAX_SL_USD) — SL du signal plafonné à 12$ de l'entrée
  • TP : current ± TP_FIXED_GAIN_USD (7$, le TP du signal est ignoré) puis recalcul dynamique au remplissage (identique ZN cas 1)
  • Log : CH{num}-PU | ACCEPTE | MK=... | L1=... | L2=...

4.2 MP — Quick Alert sans prix (« BUY NOW »)

  • Entry : prix courant au moment du signal (entry_price = current)
  • Zone : BUY [current − TOLERANCE_MP, current + TOLERANCE_MP] ; SELL [current − TOLERANCE_MP, current + TOLERANCE_MP] (avec TOLERANCE_MP = 2 par défaut) → le prix est toujours dans la zone → jamais refusé pour position hors zone (seuls les filtres généraux s'appliquent)
  • SL : current ± QUICK_ALERT_SL_OFFSET (12$) — jamais de SL dans le message
  • TP : current ± TP_FIXED_GAIN_USD (7$) — unifié (même règle que ZN/PU/QA), puis recalcul dynamique au remplissage
  • Exécution : MK + L1 + L2 (LOT_MARKET 0.01)
  • Log : CH{num}-MP | ACCEPTE | MK=... | L1=... | L2=...

4.3 QA — Quick Alert avec prix (« BUY 4439 »)

  • Entry : prix annoncé dans le message
  • Zone convertie : [entry ± TOLERANCE_PU] (3$) :
    • BUY : in_zone = entry − TOLERANCE_PU ≤ prix ≤ entry + TOLERANCE_PU
    • SELL : in_zone = entry − TOLERANCE_PU ≤ prix ≤ entry + TOLERANCE_PU
    • Prix dans la zone → MK + L1 + L2 ; sinon → REFUSE HORS ZONE (même logique que PU — pas de bande étendue)
  • SL : SL du message sinon entry ± QUICK_ALERT_SL_OFFSET, capé MAX_SL_USD ; ajusté si invalide (SL < entry BUY / > entry SELL, sinon ±10)
  • TP : current ± TP_FIXED_GAIN_USD (7$) — unifié (le TP du signal est ignoré), puis recalcul dynamique
  • Filtre distance TP : prix trop proche du TP (< 30% du trajet restant, TP_DISTANCE_MIN_RATIO) → signal ignoré
  • Log : CH{num}-QA | ACCEPTE | MK=... | L1=... | L2=...

4.4 Règles communes PU / MP / QA / ZN

  • 1 signal par canal : un nouveau signal du même canal ferme l'ancien (_close_previous_signal, commentaire NEW-SIGNAL)
  • Fusion QA/MP + PU/ZN (TEMPS_DE_FUSION = 2 minutes) :
    • Cas 1 : le signal de fusion PU/ZN arrive dans les 2 min après le signal QA/MP → FUSION ACCEPTE (pas de doublon)
    • Cas 2 : le signal de fusion PU/ZN arrive après 2 min après le signal QA/MP → FUSION ECHOUE → _close_previous_signal (le nouveau signal ferme l'ancien)
  • TP dynamique identique au ZN cas 1 : MK seul → entry_MK ± 7 (cible 7$) ; MK+L1 → avg ± 5.25 (10.5$) ; MK+L1+L2 → avg ± 4.67 (14$)
  • MK fermé (TP/SL/manuel) → L1/L2 annulées (PHASE 5 : pas de LIMIT orpheline qui se remplirait après la clôture du trade)
  • AL n'est qu'un label de log (annonce de quick alert) : l'exécution est QA ou MP, le commentaire MT5 est CH{num}-QA / CH{num}-MP (jamais -AL)

5. Gestion du TP

5.1 TP initial (tous les types)

  • TP unifié pour ZN / PU / MP / QA : TP = current ± TP_FIXED_GAIN_USD (7$) — depuis le prix d'exécution du MK (le TP du signal est ignoré). Ce TP est le même pour MK, L1 et L2.

5.2 TP dynamique (recalculé au remplissage des LIMITs)

CasPositionsP&L cibleTP = avg_entry ± (cible / nb)
11 position (MK seul, ou L3 seule)7.0 × 1 = 7.0$± 7.00$
22 positions (MK+L1, ou L3+L4)7.0 × 1.5 = 10.5$± 5.25$
33 positions (MK+L1+L2)7.0 × 2.0 = 14.0$± 4.67$

Le TP est recalculé quand le nombre de positions change (guard _tp_calculated_for) et appliqué à toutes les positions. Le SL ne bouge jamais.

Comportement réel vérifié (deals) : le recalcul cas 1 s'exécute dès le 1er cycle de la boucle (les LIMITs en attente ne comptent pas comme positions) → le TP initial est immédiatement remplacé par entry_MK ± 7. Résultat : tout MK seul ferme à +7.00$ exactement (115 trades confirmés sur la semaine, ex. CH85-ZN-MK open 4450.91 → close 4457.91 = +7.00$). Le TP initial (milieu de zone ± 7 dans le code actuel) ne survit que si le bot est down au moment du remplissage.

5.3 P&L cible (clôture globale)

Si le P&L flottant total (profit + swap) ≥ pnl_cible → le bot ferme toutes les positions et annule les LIMITs restantes (commentaire PNL-TARGET).

Conflit conceptuel connu : les TPs individuels MT5 ferment chaque position seule si atteints avant le P&L cible → fermetures partielles possibles (ex. cas CH110 du 31/08 : MK+L1 fermés au TP 4427.75, L2 restée avec son TP initial car le bot était down au moment du remplissage de L2).

7. Cycle de vie d'un signal

1
Message Telegram reçu (Telethon) → anti-spam → parser (NFKC, extraction Entry/TP/SL)
2
Traçage dans signal_tracker.json (msg_id unique → dédoublonnage)
3
Filtres : horaire → news → conflit → TV → spread → distance TP
4
1 signal par canal : _close_previous_signal ferme l'ancien signal du canal (annule LIMITs d'abord, puis ferme les positions, commentaire NEW-SIGNAL)
5
Ouverture MARKET + L1 + L2 (SL unique capé, TP initial)
6
Boucle de gestion (0.3s) : recalcul TP dynamique à chaque remplissage, SL fix, P&L cible, expiration hors-zone, nettoyage orphelins
7
Clôture : TP touché (MT5), SL touché (MT5), P&L cible (bot), nouveau signal (bot), fin de journée (TRADING_END_HOUR)
8
P&L reporté (_get_last_pnl), rapport quotidien

8. Recovery au redémarrage (v17.4g)

  • Au démarrage, le bot scanne les positions MT5 existantes (par magic + commentaire CH{num}-{prefix}) et reconstruit les entrées perdues
  • Résout le vrai nom du canal (source_channel) même si le canal a été renommé
  • Matching par numéro CHxx dans _close_previous_signal, check_conflict, _market_in_zone — évite 2 signaux du même canal après restart
  • Reconstruit avec sl_wanted → le fix SL post-ouverture corrige aussi les positions reprises
  • Recalcule le TP dynamique sur l'entrée reconstruite
  • Nettoyage des LIMITs orphelines (annulation, sauf L3/L4 hors-zone)
