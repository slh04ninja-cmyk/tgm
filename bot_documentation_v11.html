1. Vue d'ensemble & Architecture

Le bot écoute jusqu'à 19 canaux Telegram en parallèle via Telethon. Dès qu'un message est reçu :

  1. Déduplication — ignore les messages identiques reçus dans les 60 dernières secondes
  2. Filtre le spam et les messages non-trading
  3. Parse le signal (direction, entry, zone, TPs, SL)
  4. Valide (spread, SL, conflit, horaire, news, max positions, P&L quotidien, TimesFM)
  5. Exécute UN SEUL ordre MARKET par signal (SINGLE_POSITION_MODE)
  6. Gère le BE (Break Even) et le gain fixe par position
  7. Limite le P&L quotidien
Telegram Channels (1-19) ↓ Déduplication → hash(contenu + canal) — ignore doublons dans les 60s ↓ Signal Parser → TradeSignal {direction, entry, zone, TPs, SL} ↓ Validation : spread / SL / conflit / horaire / news / max positions / P&L / TimesFM ↓ Conversion Zone → Prix Unique → midian (ex: 4000-4010 → 4005) ↓ MT5Bridge → UN SEUL place_market_order (pas de LIMIT) ↓ TradeManager → BE + Gain fixe + P&L quotidien (poll 1s) ↓ Alertes Telegram → notifications (dédupliquées aussi)

2. Changements V11 vs V10

Changement fondamental : En V11, un seul ordre MARKET est placé par signal. Plus de LIMIT, plus de pending orders, plus de positions multiples.

2.1 Ce qui a changé

FonctionnalitéV10V11
ExécutionMARKET + LIMIT (2 positions)UN SEUL MARKET
Signaux zoneCAS1, CAS2-a, CAS2-b (2 positions)Converti en Prix Unique (midian)
Quick AlertAL-MP + AL-LMT (market ou limit)AL-MP uniquement + tolérance prix
FusionQA + LIMIT (2ème position)SL/TP mis à jour sur QA existant
BESL @ entry, fermeture manuelleSL @ entry + TP @ entry ± TP_FIXED_GAIN (MT5 ferme auto)
FermetureManuelle par le botMT5 ferme auto quand TP atteint
Canaux919
ValidationAucuneTimesFM (optionnel)
DéduplicationAucuneHandler + Alertes

2.2 Pourquoi SINGLE_POSITION_MODE ?

  • Simplicité : un signal = un trade = un ticket à suivre
  • Risque contrôlé : pas de multiplication des positions
  • P&L prévisible : gain/perte connu à l'avance (TP_FIXED_GAIN_USD)
  • Pas de pending orders : pas d'ordres qui traînent et se remplissent au mauvais moment

3. Signal Parser

3.1 Pipeline de normalisation

Le texte brut est nettoyé en 15 étapes avant extraction :

Texte brut : " 🟢 BUY X AU/USD @3 3 4 0 TP1 3345 SL: 3330 " ↓ 1-2. Supprimer caractères invisibles (zero-width, U+00A0) 3. Convertir superscripts : ¹→1, ²→2 4-5. Supprimer astérisques, S/L → SL 6-7. Supprimer () [] {} emojis guillemets, séparateurs → espace 8-9. Fusionner symboles : X AUUSD → XAUUSD 10. Supprimer préfixes parasites 11-15. Normaliser espaces + UPPER ↓ Résultat : "BUY XAUUSD 3340 TP1 3345 SL 3330"

3.2 Extraction

ComposantMéthodeVariantes
DirectionRegex + mappingBUY, SELL, LONG, SHORT, ⬆/⬇
SymboleRegex + SYMBOL_MAPGOLD, XAU/USD, XAGUSD, USOIL, BTCUSD
Zone12 patterns4199/4203, 4199:4203, ENTRY 3240, BUY 4512
TPsRegex TP/T/TAKE PROFITTP1, TP¹, TARGET, TGT
SLRegex SL/STOPSL, STOP LOSS

3.3 Génération automatique

SL auto : Si TPs mais pas de SL → distance moyenne TPs × 1.5
TP auto : Si SL mais pas de TP → RR_RATIO_DEFAULT=1.5
Quick Alert : Si ni TP ni SL → SL provisoire ±10 points, TP ±15 points

6. Quick Alert (QA)

6.1 Types de Quick Alert

TypeFormatPrixToléranceExécution
Sans prixALERT, BUY NOW, SELL MARKETAucunAucuneMARKET au prix actuel
Avec prixSELL XAUUSD @ 4030Dans le signal± QA_PRICE_TOLERANCEMARKET si prix dans tolérance
AL-MP (Type 1) et Market Price sont identiques : les deux sont des signaux sans prix (is_market_price=True) qui s'exécutent au prix actuel du marché. Le nom change selon le canal d'origine, mais le comportement est le même.

6.2 Flux d'exécution

Quick Alert reçue : BUY XAUUSD @ 4095 ↓ Vérification MAX_POSITIONS : 3 max → OK ↓ Résolution symbole : XAUUSD → XAUUSDm ↓ Prix actuel : 4100.745 ↓ is_market_price ? ├─ OUI (Type 1) → SL/TP auto, pas de vérif tolérance └─ NON (Type 2) → vérifier tolérance ↓ |current - entry| ≤ QA_PRICE_TOLERANCE ? ├─ OUI → exécuter └─ NON → ANNULÉ ↓ ❌ QA ANNULÉE | BUY XAUUSD Prix: 4100.745 | Entry signal: 4095.0 Écart: 5.7 > 3.0

6.3 Tolérance de prix QA

Si le signal Quick Alert contient un prix (Type 2), le bot vérifie que le prix actuel est dans [entry ± QA_PRICE_TOLERANCE].

Entrée signalPrix actuelÉcartToléranceRésultat
4095.04096.51.5$3.0$EXÉCUTÉ
4095.04100.75.7$3.0$ANNULÉ
4030.04097.167.1$3.0$ANNULÉ
Pourquoi un signal est annulé ? Si le canal envoie "BUY @ 4095" mais que le marché est déjà à 4100, l'écart de 5.7$ dépasse la tolérance de 3$. Le bot refuse d'entrer à un prix trop éloigné de celui demandé. Augmentez QA_PRICE_TOLERANCE dans .env si nécessaire.

6.4 Filtre distance TP

Un Quick Alert est ignoré si le prix est trop proche du TP (moins de 30% du chemin restant) :

Exemple : BUY @ 4512, TP=4527, prix actuel=4525 Distance restante : 4527 - 4525 = 2 points Distance totale : 4527 - 4512 = 15 points Ratio : 2/15 = 13% < 30% → IGNORÉ

7. Fusion QA + Signal complet

7.1 Principe

Quand un signal complet arrive après un Quick Alert, le bot fusionne les deux au lieu d'ouvrir une 2ème position :

  • Le SL/TP de la position QA est mis à jour avec les vrais SL/TP du signal complet
  • Pas de 2ème position (SINGLE_POSITION_MODE)

7.2 Détection de fusion

Signal complet reçu : SELL zone 4028-4032, TP=4010, SL=4045 ↓ Chercher QA existant : key = "CH15_XAUUSD_SELL" ↓ QA trouvé ? ├─ OUI → vérifier prix QA dans zone ± FUSION_TOLERANCE └─ NON → exécuter signal complet normalement ↓ entry_QA ∈ [zone_low - 3, zone_high + 3] ? ├─ OUI → FUSION : modifier SL/TP └─ NON → annuler QA + exécuter signal complet

7.3 Scénarios de fusion (V11)

Scénario 1 : QA Market Price → Fusion

18:00 — Quick Alert : SELL XAUUSD @ 4030 → MARKET #11111 @4030.5 (quick_market) 18:05 — Signal complet : SELL zone 4028-4032, TP=4010, SL=4045 → entry QA (4030) ∈ [4028-3, 4032+3] = [4025, 4035] → FUSION Action : → Position #11111 : SL=4045, TP=4010 (mis à jour) → PAS de 2ème position Résultat : ✅ FUSION SL/TP mis à jour QA : #11111 Nouveau SL: 4045.0 | Nouveau TP: 4010.0 Canal: GOLD BASICS ACADEMY

Scénario 2 : QA hors tolérance → Annulation

18:00 — Quick Alert : SELL XAUUSD @ 4030 → MARKET #11112 @4030.5 18:05 — Signal complet : BUY zone 4090-4100, TP=4120, SL=4080 → entry QA (4030) ∉ [4090-3, 4100+3] = [4087, 4103] → HORS TOLÉRANCE Action : → Fermer position #11112 (QA annulé) → Exécuter signal complet : MARKET BUY @4095 Résultat : ⚠️ FUSION ÉCHOUÉE | SELL QA Market Price annulé (hors ±3) P&L : +2.50 $ Signal complet exécuté Canal: GOLD BASICS ACADEMY

8. Gestion BE + Gain fixe

8.1 Fonctionnement

Le Break Even (BE) protège les positions en gain en déplaçant le SL au prix d'entrée et en fixant un TP de gain.

Position ouverte → prix bouge ↓ Chaque seconde (_check_all) : ↓ PNL de la pire position ≥ PNL_TRIGGER_USD (8$) ? ├─ OUI → BE ACTIVÉ └─ NON → continuer à surveiller ↓ BE activé : → SL = entry_price (prix d'entrée) → TP = entry_price ± TP_FIXED_GAIN_USD (15$) → MT5 ferme automatiquement quand le prix atteint le TP

8.2 Whitelist des rôles BE

Seules certaines positions peuvent déclencher le BE :

RôleDescriptionBE ?
market_singlePosition MARKET (PU1, PU2, ZN1, ZN2)OUI
quick_marketQuick Alert MARKET (AL-MP)OUI
quick_limitQuick Alert LIMIT (ancien)NON
merge_limitFusion LIMITNON

8.3 Exemple BE complet

18:00 — Signal : BUY XAUUSD @ 4005, TP=4050, SL=3980 → MARKET #200 @4005.0 18:10 — Prix monte à 4013.5 : PNL = 8.50$ ≥ PNL_TRIGGER_USD(8$) → BE ACTIVÉ → SL = 4005.0 (entry) → TP = 4005.0 + 15.0 = 4020.0 (entry + TP_FIXED_GAIN_USD) 18:25 — Prix atteint 4020.0 : TP touché → MT5 ferme automatiquement P&L = +15.00$ (TP_FIXED_GAIN_USD) Messages Telegram : ✅ BE ACTIVÉ | BUY XAUUSD ━━━━━━━━━━━━━━━━━━ Position #200 | SL → 4005.0 Gain fixe: 15.0$ Canal: Alixza Gold Trading ✅ TP-FIXED | BUY XAUUSD ━━━━━━━━━━━━━━━━━━ Position #200 fermée P&L: +15.00$ Canal: Alixza Gold Trading

8.4 Paramètres BE

Variable .envDéfautDescription
TP_FIXED_ENABLEDtrueActiver le BE + gain fixe
TP_FIXED_GAIN_USD15.0Gain fixe en dollars (TP = entry ± ce montant)

Comment ça marche : Le BE place SL @ entry et TP @ entry ± 15$. Quand le prix atteint le TP, MT5 ferme la position automatiquement. Le bot n'a plus besoin de surveiller et fermer manuellement.

9. TP_TRIGGER

9.1 Principe

Le TP_TRIGGER annule les ordres pending restants quand le prix atteint un certain niveau. En V11 (SINGLE_POSITION_MODE), il n'y a normalement pas de pending orders, mais ce mécanisme reste actif pour les cas de fusion.

9.2 Logique

Nombre de TPsTP_TRIGGER
1 TPTP1
2 TPsTP2
3+ TPsTP3

9.3 Exemple

Signal : BUY XAUUSD, TPs=[4020, 4030, 4050] TP_TRIGGER = TP3 = 4050 Si prix atteint 4050 : → Annuler tous les pending orders de cette entrée → Position ouverte reste active (si elle existe)

10. P&L Quotidien

10.1 Mécanisme

Le bot suit le P&L quotidien (réalisé + flottant). Si la limite est atteinte, toutes les positions sont fermées et aucun nouveau trade n'est accepté.

Chaque seconde : ↓ total_pnl = daily_pnl (réalisé) + floating_pnl (flottant) ↓ total_pnl ≥ DAILY_PROFIT_LIMIT (30$) ? ├─ OUI → SHUTDOWN : fermer tout, annuler pending └─ NON → continuer ↓ Reset quotidien à TRADING_START_HOUR (3h UTC)

10.2 PNL réaliste — Fix V11

Le P&L est maintenant mis à jour après CHAQUE fermeture de position, quel que soit le type de fermeture :

Chemin de fermeturePNL update
TP-FIXED (gain fixe atteint)OUI
Daily limit shutdownOUI
SL/TP touché (poll loop)OUI
NewsManager (fermeture avant news)OUI
Conflict closeOUI
Signal CLOSE TelegramOUI
Fusion fail (QA annulé)OUI
Remplacement signal (1-per-channel)OUI

10.3 Récupération au démarrage

Au démarrage, le bot récupère le P&L des 3 derniers jours via mt5.history_deals_get(). Les deals de clôture (DEAL_ENTRY_OUT) sont indexés par le magic du deal d'ouverture (DEAL_ENTRY_IN) pour gérer les fermetures manuelles (magic=0).

12. Validation TimesFM

12.1 Principe

TimesFM est un modèle de prévision de séries temporelles de Google (200M paramètres). Le bot l'utilise pour valider la direction des signaux avant exécution.

Signal reçu : BUY XAUUSD ↓ Récupérer 256 dernières bougies M5 depuis MT5 ↓ TimesFM 2.5 → prédit les 12 prochaines bougies ↓ Analyse : direction prédite, amplitude (pips), confiance ↓ Direction = signal ET move ≥ 5 pips ET confiance ≥ 0.35 ? ├─ OUI → signal accepté └─ NON → signal REJETÉ

12.2 Critères de validation

CritèreSeuilVariable .env
Direction préditeDoit correspondre au signal—
Amplitude minimale5.0 pipsTIMESFM_MIN_MOVE_PIPS
Confiance minimale0.35TIMESFM_MIN_CONFIDENCE

12.3 Exemple

Signal : BUY XAUUSD TimesFM : Prédit: BUY (move=8.2 pips, conf=0.72) → ✅ VALIDÉ Autre cas : Prédit: SELL (move=3.1 pips, conf=0.28) → ❌ REJETÉ Raison: direction prédite=SELL ≠ signal=BUY

13. Déduplication

13.1 Niveau Handler

Le bot déduplique les messages Telegram entrants pour éviter le double traitement (ex: canal + groupe de discussion lié).

Message reçu : BUY XAUUSD @ 4095 ↓ Clé = hash(texte) + nom_canal ↓ Déjà vu dans les 60 dernières secondes ? ├─ OUI → ignoré (DEDUP) └─ NON → traiter normalement

13.2 Niveau Alertes

Les messages d'alerte Telegram sont aussi dédupliqués : si le même message d'alerte a été envoyé dans les 10 dernières secondes, il est ignoré.

13.3 Pourquoi ?

Telegram peut livrer le même message via un canal ET son groupe de discussion lié. Sans déduplication, le bot traiterait le signal deux fois → double position, double alerte.
